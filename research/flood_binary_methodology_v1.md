# Flood_Binary Methodology v1

## Status

Methodology only. No binary target or negative labels are generated by this document.

## Confirmed facts

- The cleaned IFI event inventory contains 6,876 recorded flood-event rows and 6,876 unique `uei` values.
- The inventory is an event record, not a complete district-time panel.
- There are 20 missing `start_date` values and 20 missing `end_date` values.
- District plus year is not a unique event identity.
- IFI absence cannot be interpreted as verified no flooding.
- The approved working design is district-week, 26-week history, and a seven-day horizon.

## Proposed observation unit

One observation will represent:

`verified_district_id × approved_week`

The district identifier must come from the reviewed LGD/Census crosswalk and an approved boundary-vintage policy. The weekly convention, such as ISO week or a project-defined local week, must be fixed before implementation.

## Prediction cutoff and horizon

- Cutoff: the final timestamp of the approved current district-week.
- Horizon: the seven calendar days immediately after the cutoff.
- Features: only data available through the cutoff, plus any separately approved forecast data issued before the cutoff.
- Event dates and impacts used to assign the label are target/reference data, never predictive features.

Because IFI dates are date-level rather than reliable time-of-day observations, the implementation must define a date-only overlap convention. Events with missing `start_date` are excluded from automatic target assignment and retained in an unresolved-data report unless independently resolved.

## Positive observation rule

A district-week is positive when an independent event frame confirms at least one IFI event interval associated with the district overlaps the seven-day forecast window. The event linkage must:

1. Use `uei` for event grouping only.
2. Use the approved district crosswalk and boundary vintage.
3. Retain all overlapping `uei` values as audit metadata.
4. Preserve multiple events rather than collapsing them silently.
5. Define how an event with an unknown end date is handled.

The preferred event evidence is the IFI event record, but positive assignment must still pass geographic and temporal reconciliation.

## Negative observation rule

A district-week is negative only when an independent, documented observation frame explicitly supports non-flood status for that district-week. The source must document coverage, flood definition, observation process, temporal resolution, district identifiers, and false-negative limitations.

“No IFI event found” is not a negative rule.

The safest required source is an authoritative or systematically documented district-time flood surveillance/exposure frame covering the selected period. A rainfall-only absence rule is insufficient because rainfall does not prove whether flooding occurred.

## Exclusion rules

Exclude or quarantine observations with:

- missing district identity after crosswalk review;
- missing event start date when positive assignment depends on it;
- unresolved boundary-vintage conflicts;
- contradictory or ambiguous event-to-district assignment;
- insufficient independent observation coverage for a negative label;
- target-window information that would only be known after the cutoff.

Do not turn excluded observations into negatives.

## Uncertainty handling

Store observation-level flags for date uncertainty, crosswalk status, event count, boundary vintage, external-frame coverage, and negative-source confidence. Do not convert uncertainty into a binary label without an approved rule. Sensitivity analyses should compare strict and inclusive event-overlap policies after the observation frame is available.

## Required inputs before implementation

- Approved district-week calendar and timezone.
- Seven-day overlap convention for date-only IFI records.
- Independent district-week non-event/event frame.
- Approved fixed or historical boundary policy.
- Policy for missing start/end dates.
- Versioned LGD/Census crosswalk review.
- Rainfall cutoff policy, if rainfall is used as a predictor.

## Leakage prohibition

`uei`, `start_date`, `end_date`, duration, impact fields, flooded-area measures, and any future observation used to determine the label must not become predictive features. `uei` is permitted only for grouping, linkage, duplicate checks, and contamination checks.
